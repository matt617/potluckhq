# Relationship field UX audit

Existing people and records should be found and selected by name, with the destination and consequence visible before saving. Membership and ownership require the recipient’s acceptance. Recipe copies, meal assignments and import destinations can be saved directly by an authorized member.

The previous membership form only generated bearer invitation links. It had no member lookup or named request inbox. This implementation adds **search → select → nominate → accept or decline**, while keeping links available for people new to Potluck.

## Interaction rules

Search text never becomes a relationship value. Only selecting a returned record sets its ID. Pickers retain the chosen name, support changing or clearing optional relationships, and explain missing records instead of displaying an ID. Escape closes the picker before closing its surrounding form. Labels and hints remain connected to controls for assistive technology.

A nomination is pending, accepted, declined, withdrawn or expired. Pending requests appear next to member search; the recipient’s inbox explains the role before acceptance. Acceptance consumes the request and adds membership under one transaction, enforcing capacity even when people act concurrently. Duplicate nominations, unauthorized acceptance, expiration and withdrawal are rejected server-side. No email or external message is sent by this flow.

## Search scope and operational limits

Name search covers people in the requester’s existing kitchens and circles. Other accounts require an exact email address. Results expose a display name, shared-space or exact-email context, and membership status; dietary, billing and unrelated profile fields are not returned. This scope is the default chosen for this pass, pending any preference for a broader public member directory.

Existing profiles do not have a directory index. Exact-email search uses bounded, paginated profile scans and offers “Continue searching” when more of the database remains. This works with existing accounts without a migration, but an indexed, normalized email lookup should replace scans before substantial growth. A public name directory would also need a deliberate discoverability policy and indexed search.

The inbox refreshes every 30 seconds while visible. Nomination delivery is in-app. Link invitations remain available for account creation. Production deployment and checks against live accounts are separate from the local implementation and fixture-based verification.
